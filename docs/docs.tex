    \section{Introduction}
    TestA is a domain-specific language designed for generating structured 
    test data in formats like JSON, CSV, and XML. It provides a simple, 
    C-like syntax for defining templates, resources, enums, and generation
    rules, enabling quick and expressive data mockups for testing, prototyping, 
    or seeding.
    \begin{listing}[h]
    \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
|\textcolor{directiveColor}{@output}| csv {
    header = true;
    quote = true;
    delimiter = ";";
}
|\textcolor{directiveColor}{@output\_path}| "./example.csv";

|\textcolor{keywordColor}{type}| Grade = int[range=6..=10];
|\textcolor{keywordColor}{type}| GradeList = [|\textcolor{purple}{Grade}|][count=0..=50];

enum |\textcolor{black}{Role}| { 
    User => 10; 
    Admin => 2;
    Other;
};

|\textcolor{keywordColor}{template}| User {
    id = $uuid();
    name = |\textcolor{purple}{string}|;
    role = |\textcolor{purple}{Role}|;
}

|\textcolor{keywordColor}{template}| |\textcolor{black}{Student}| : User {
    year = int [range=1..=4];
    grades = |\textcolor{purple}{GradeList}|;
}

|\textcolor{directiveColor}{@generate}| User [10];
    \end{minted}
    \centering
    \caption{testA example}
    \label{listing:example}
    \end{listing}

    \section{Features}
    \subsection{Templates}
    \begin{listing}[h]

    \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
template <name> [: <parent_name>] {
    [override] <name1> = <expr>;
    [override] <name1> = <expr>;
    ...
}
    \end{minted}
    \centering
    \caption{Template declaration}
    \label{declaration:template}
    \end{listing}
    \par Templates are blueprints for creating reusable data structures or 
    types that are used in a "generate" expression. Each template has 
    a name and a set of fields, where each field is a pair consisting 
    of a string (the field name) and an expression (which defines the 
    field's value). By using data types and enumerations within these 
    expressions, you can add randomness to the values generated by the 
    template.
    \begin{listing}[h]
        \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
template User {
    id = int;
    name = |\textcolor{purple}{string}|;
    age = int;
}
        \end{minted}
        \caption{Example template in testA}
        \centering
        \label{listing:1}
    \end{listing}
    \subsubsection{Inheritence}
    \begin{listing}[h]
        \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
template User { age = int [range=0..=100]; }
template Student : User {
    year = int[range=1..=4];
    override age = int[range=19..=30];
}

        \end{minted}
        \caption{Inheritence example}
        \centering
        \label{listing:inheritance_example}
    \end{listing}

    \par Templates can be created from existing templates through a process 
    known as inheritance (Listing \ref{listing:inheritance_example}). A child template inherits all the fields from its 
    parent template and has the option to override any specific field by using 
    the "override" keyword and specifying the field name. 
    \par While using this keyword is not mandatory, incorrect usage may lead to a warning. 
    For example, Listing \ref{listing:override_example} will trigger a warning because the 
    field "age" is not overridden in the child template. It's important to note that all 
    repeated fields are overridden by default.
    \begin{listing}[h]
        \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
template User { 
    id = string;
    //age = int [range=0..=100]; 
}
template Student : User {
    year = int[range=1..=4];
    // User template does not have 'age' field!
    override age = int[range=19..=30];
}

        \end{minted}
        \caption{Override example}
        \centering
        \label{listing:override_example}
    \end{listing}

    \begin{listing}[h]

        \caption{Enumeration declaration}

    \par The "testA" enumerations include a list of names and their corresponding weights, which indicate the likelihood of randomly generating a variant. 
    Weights are always integers, with a default value of one if not specified.
    \begin{listing}[h]
        \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
enum |\textcolor{black}{Role}| {
    User => 8;
    Admin; // Default weight is 1
    Developer => 3;
}
        \end{minted}
        \caption{Enumerations in testA}
        \centering
        \label{listing:2}
    \end{listing}

    \subsection{Data types}
    \par Unlike other programming languages, such as C or Java, testA data types represent random values in expressions. 
    There are four fundamental data types available: integers (ints), floating-point numbers (floats), strings, and booleans.
    \begin{listing}[h]
        \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
template User {
    // Generates random string
    name = |\textcolor{purple}{string}|; 
    // Generates random integer
    age = int + 18; 
    // Generates random float
    salary = float + 300.0; 
    // Generates random boolean
    is_registered = !bool; 
}
        \end{minted}
        \caption{Template with data types}
        \label{listing:4}
    \end{listing}
    \par As shown in Listing \ref{listing:4}, these types can interact with one another as well as with 
    literals. Additionally, fundamental data types can be extended by introducing constraints or creating 
    lists of these types.
    \subsubsection{Lists}
        \begin{listing}[h]
        \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
[<type>][<constraint1>, <constraint2>...]  
        \end{minted}
        \caption{List type}
        \centering
        \label{declaration:list}
    \end{listing}
    \par A list is a container that can hold various data types, including other lists. By default, a list generates a 
    random number of items, ranging from 0 to 16. However, this number can be adjusted using the "count" constraint. 
    Further details about constraints can be found in the next section.
    \begin{listing}[h]
        \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
// Example 1: List.
[int][count=5..15] 
// [1, -5, 6, -7, 8, 18]
// Example 2: Multidimensional list.
[[int[range=1..=5]][count=1..5]][count=3..=5]  
// [[1,2,3],[5,2,1,3],[5],[4,5]]
        \end{minted}
        \caption{List examples}
        \centering
    \label{listing:list_example}
    \end{listing}
    \par In Examples from Listing \ref{listing:list_example}, two lists are declared. Second list can be 
    simplified by utilizing type constraints.

    \subsubsection{Type constraints}
    \begin{listing}[h]
        \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
|\textcolor{keywordColor}{type}| <name> = <type> [<constraint1>, <constraint2>...];
|\textcolor{keywordColor}{type}| <name> = |\textcolor{keywordColor}{extend}| <type> |\textcolor{keywordColor}{with}| [<constraint1>, ...];
        \end{minted}
        \caption{Constrained type declaration}
        \label{declaration:type_constraint}
    \end{listing}

    \par The previous example (Listing \ref{listing:4}) does not depict a realistic individual, as the fields for age 
    and salary could potentially contain negative values. To address this issue, we can implement type constraints to prevent such errors. 
    These constraints can be easily added by enclosing them in brackets [ ] after the type name (Listing \ref{listing:5}), ensuring that the data 
    conforms to the expected parameters.
    \begin{listing}[h]
        \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
template User { age = int [range=0..=100]; }
template Student : User { 
    override age = int[range=19..=100];
    grades = [int[range=6..=10]][count=0..=46]; 
}
        \end{minted}
        \caption{Templates with constrained data types}
        \centering
        \label{listing:5}
    \end{listing}
    \par To improve clarity and minimize redundancy, types may be effectively declared and reused (Listings \ref{listing:6} and \ref{listing:int_tensor}). 
    \begin{listing}[h]
    \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
|\textcolor{keywordColor}{type}| Age = int [range=0..=100];
|\textcolor{keywordColor}{type}| StudentAge = |\textcolor{keywordColor}{extend}| |\textcolor{purple}{Age}| |\textcolor{keywordColor}{with}| [min=19];
|\textcolor{keywordColor}{type}| Grade = int [range=6..=10];
|\textcolor{keywordColor}{type}| GradeList = [|\textcolor{keywordColor}{Grade}|][count=1..=46];

template User { age = |\textcolor{purple}{Age}|; }
template Student : User { 
    override age = |\textcolor{purple}{StudentAge}|;
    grades = |\textcolor{purple}{GradeList}|; 
}
        \end{minted}
        \caption{Templates with user-defined data types}
        \centering
        \label{listing:6}
    \end{listing}
    \pagebreak

    \begin{listing}[h]
        \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
|\textcolor{keywordColor}{type}| IntList = [int][count=1..=5];
|\textcolor{keywordColor}{type}| IntMatrix = [|\textcolor{purple}{IntList}|][count=1..=5];
|\textcolor{keywordColor}{type}| IntTensor = [|\textcolor{purple}{IntMatrix}|][count=1..=5];
// same as

    \subsubsection{String patterns}
    \par String patterns define the structure of a string. In these patterns, 
    characters wrapped in \$\{\} represent placeholders where random values will be generated. Placeholders are:
    \begin{itemize}
        \item \$\{a\} generates a random lowercase letter (a-z)
        \item \$\{A\} generates a random uppercase letter (A-Z)
        \item \$\{\#\} generates a random digit (0-9)
    \end{itemize}
    Examples (Listing \ref{listing:string_pattern}) can generate "pattern: abcABCD123"
    \begin{listing}[h]
        \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
|\textcolor{keywordColor}{string\_pattern}| "pattern: ${aaaAAAA###}"; 
        \end{minted}
        \caption{String pattern example}
        \centering
        \label{listing:string_pattern}
    \end{listing}
    \par Placeholders can be used directly within the template, as demonstrated in Listing \ref{listing:string_pattern_in_template}.
    \begin{listing}[H]
        \begin{minted}[escapeinside=||, xleftmargin=1em, breaklines]{cpp}
|\textcolor{keywordColor}{template}| User {
    id = int;
    name = |\textcolor{keywordColor}{string\_pattern}| "${Aaaaaaaaa}";
    email = |\textcolor{keywordColor}{string\_pattern}| "${aaaaa##}@${aaaaa}.com"
}
        \end{minted}
        \caption{String pattern in template example}
        \centering
        \label{listing:string_pattern_in_template}
    \end{listing}
